# Reference: physics, constraints and vehicles
Load it for: doors, elevators and moving platforms, vehicles, swinging and spinning things, ropes, welding, network ownership, things that fall over or fly away

## Anchored or simulated
- **Anchored** parts never move by physics. Move them with tweens or CFrame (reference `animation`). Use this for scripted doors, lifts and platforms: it is predictable.
- **Unanchored** parts are simulated. Join them into assemblies with welds and constraints. Use this for vehicles, ragdolls, swinging and pushable things.
- A model that should move as one rigid piece: one root part, every other part welded to it with `WeldConstraint`, only the root anchored (or none, if simulated).
```lua
local function weldTo(root: BasePart, model: Model)
	for _, part in model:GetDescendants() do
		if part:IsA("BasePart") and part ~= root then
			local weld = Instance.new("WeldConstraint")
			weld.Part0, weld.Part1 = root, part
			weld.Parent = part
			part.Anchored = false
		end
	end
end
```
- Move models with `model:PivotTo(cframe)`; set `PrimaryPart` and the pivot deliberately.

## Platforms players ride
- Players only ride a platform that moves by physics. An anchored part moved by CFrame slides out from under them.
- Use an unanchored platform driven by `AlignPosition` + `AlignOrientation` (RigidityEnabled or high responsiveness) toward a target attachment you tween, or a `PrismaticConstraint` with `ActuatorType = Servo`. Give the platform high density or set constraints' max force high enough to carry players.
- Keep network ownership on the server for shared platforms: `platform:SetNetworkOwner(nil)`.

## Constraints (each needs two Attachments)
| Want | Use |
| --- | --- |
| Door, wheel, lever turning on one axis | `HingeConstraint` (`ActuatorType` None / Motor / Servo) |
| Sliding door, piston, lift | `PrismaticConstraint` |
| Ragdoll joint, chain link | `BallSocketConstraint` |
| Rope, swing | `RopeConstraint`; `RodConstraint` for fixed length |
| Suspension, bouncy things | `SpringConstraint` |
| Glue two parts rigidly | `WeldConstraint` |
| Stop two parts colliding | `NoCollisionConstraint` |
| Push or steer a body | `LinearVelocity`, `AngularVelocity`, `VectorForce`, `AlignPosition`, `AlignOrientation` |
- Attachment orientation defines the axis: a hinge turns about its attachments' X axis. Wrong axis is the usual cause of a door that will not swing.
- Never use the legacy `BodyVelocity`, `BodyGyro`, `BodyPosition`, `BodyForce`.

## Doors
- Simple and reliable: anchored door, tween its CFrame about the hinge edge, toggled by a `ProximityPrompt` on the server. Disable the prompt while it moves.
- Physical swing door: unanchored door, `HingeConstraint` to an anchored frame, `LimitsEnabled` with angle limits, Servo to hold it shut.
- Sliding: tween an anchored part, or a Servo `PrismaticConstraint`.

## Vehicles
- A `VehicleSeat` gives `Throttle` and `Steer` (-1, 0, 1) and tells you the occupant.
- Chassis: one root body part; four wheels (cylinders, axle along X) each on a `HingeConstraint` with `ActuatorType = Motor`; front wheels hang from steering parts that turn on a Servo hinge (vertical axis). `SpringConstraint`s between body and wheel carriers for suspension if wanted.
```lua
seat:GetPropertyChangedSignal("Throttle"):Connect(function()
	for _, motor in driveMotors do
		motor.AngularVelocity = seat.Throttle * MAX_SPEED
		motor.MotorMaxTorque = TORQUE
	end
end)
seat:GetPropertyChangedSignal("Steer"):Connect(function()
	for _, servo in steerServos do servo.TargetAngle = seat.Steer * MAX_STEER_ANGLE end
end)
```
- Give the driver network ownership while seated (`root:SetNetworkOwner(player)`), back to the server (`nil`) on exit: this is what makes driving feel responsive.
- Wheels: high friction (`CustomPhysicalProperties`), wheels must not collide with the body (collision groups or `NoCollisionConstraint`).
- Low centre of mass (a heavy invisible part under the floor) stops rolling over.
- Simple arcade alternative: no wheels simulated; a single body with `LinearVelocity` and `AngularVelocity` driven by the seat, plus raycast hover. Ask which the user wants: arcade or simulated.
- Boats and planes: same idea with forces; water uses terrain buoyancy or `VectorForce`.

## Network ownership
- Unanchored parts are simulated by whichever machine owns them. Automatic ownership hands parts to the nearest player, which causes stutter when ownership flips and lets exploiters move them.
- Server authority (enemies, shared platforms, anything that matters): `part:SetNetworkOwner(nil)` on the assembly root.
- Player-driven (their vehicle): `SetNetworkOwner(player)`.
- Only call it on unanchored assemblies; it errors on anchored parts.

## Collision groups
```lua
local PhysicsService = game:GetService("PhysicsService")
PhysicsService:RegisterCollisionGroup("Players")
PhysicsService:CollisionGroupSetCollidable("Players", "Players", false)
part.CollisionGroup = "Players"
```
Use for players passing through each other, vehicles ignoring their own wheels, team doors.

## When physics misbehaves
- Flies off or explodes: two unanchored parts spawned overlapping, or constraints fighting. Separate them or add `NoCollisionConstraint`.
- Jitters: mass ratio too extreme, or ownership flipping. Raise the light part's density; set ownership explicitly.
- Falls through the floor: moving too fast for thin parts; thicken the floor or cap speed.
- Will not move: something in the assembly is anchored, or the actuator's max force/torque is 0 (the default for some).
- Drifts or tips: centre of mass too high; check `AssemblyCenterOfMass`.
- Massless helper parts: `Massless = true` on decoration welded to a body.
