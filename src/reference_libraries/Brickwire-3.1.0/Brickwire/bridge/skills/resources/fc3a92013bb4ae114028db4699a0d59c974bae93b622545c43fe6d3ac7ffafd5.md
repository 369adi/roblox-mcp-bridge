# Reference: monetization
Load it for: gamepasses, developer products, Robux purchases, premium benefits, ProcessReceipt

You cannot create gamepasses or products, set prices, or see the user's ids. The user creates them on the Creator Dashboard and gives you the ids. **Always ask for the ids. Never invent one**; put each in a clearly named constant in one shared module so they are easy to change.

## Two kinds
| | Gamepass | Developer product |
| --- | --- | --- |
| Bought | once, permanent | any number of times |
| Use for | VIP, 2x coins, permanent perks | currency packs, boosts, revives |
| Check | `UserOwnsGamePassAsync` | no ownership: grant in `ProcessReceipt` |
| Prompt | `PromptGamePassPurchase` | `PromptProductPurchase` |

## Gamepasses
```lua
local MarketplaceService = game:GetService("MarketplaceService")
local owns: { [Player]: { [number]: boolean } } = {}

local function hasPass(player: Player, passId: number): boolean
	owns[player] = owns[player] or {}
	if owns[player][passId] ~= nil then return owns[player][passId] end
	local ok, result = pcall(MarketplaceService.UserOwnsGamePassAsync, MarketplaceService, player.UserId, passId)
	if ok then owns[player][passId] = result end
	return ok and result
end

MarketplaceService.PromptGamePassPurchaseFinished:Connect(function(player, passId, purchased)
	if purchased then
		owns[player] = owns[player] or {}
		owns[player][passId] = true
		applyPass(player, passId)   -- give the perk now, without rejoining
	end
end)
```
- Check on the server, cache per session, clear on `PlayerRemoving`. Ownership checks fail sometimes: `pcall`, and treat failure as "not owned for now", retry later.
- Apply perks on join and on purchase. A perk that only appears after rejoining is a bug.
- The prompt is opened from the client (`MarketplaceService:PromptGamePassPurchase(player, id)`), usually from a shop button.

## Developer products
There is **one** `ProcessReceipt` for the whole game. If the place has one already, extend its product table; never assign a second.
```lua
local handlers: { [number]: (player: Player) -> boolean } = {
	[COINS_100] = function(player) return Currency.Add(player, 100, "purchase") end,
}

MarketplaceService.ProcessReceipt = function(receipt)
	local player = Players:GetPlayerByUserId(receipt.PlayerId)
	if not player then return Enum.ProductPurchaseDecision.NotProcessedYet end
	local profile = PlayerData.Get(player)
	if not profile then return Enum.ProductPurchaseDecision.NotProcessedYet end
	if profile.Receipts[receipt.PurchaseId] then return Enum.ProductPurchaseDecision.PurchaseGranted end
	local handler = handlers[receipt.ProductId]
	if not handler then return Enum.ProductPurchaseDecision.NotProcessedYet end
	local ok, granted = pcall(handler, player)
	if not ok or not granted then return Enum.ProductPurchaseDecision.NotProcessedYet end
	profile.Receipts[receipt.PurchaseId] = true      -- saved with the profile
	return Enum.ProductPurchaseDecision.PurchaseGranted
end
```
- Return `PurchaseGranted` only after the reward is in the player's data. `NotProcessedYet` makes Roblox call again later, including after rejoin, so grants must be idempotent: record `PurchaseId`s in the saved profile (keep the most recent 50 to 100).
- Never grant from `PromptProductPurchaseFinished`; it is only a UI signal.
- Without saved data the grant cannot be made safe; say so if the game has no saving.

## Premium
- `player.MembershipType == Enum.MembershipType.Premium`, and `Players.PlayerMembershipChanged` for upgrades during play. Offer with `MarketplaceService:PromptPremiumPurchase(player)`.

## Showing prices
- `MarketplaceService:GetProductInfo(id, Enum.InfoType.GamePass or .Product)` in `pcall` gives `PriceInRobux` and `Name`. Cache it. Show the Robux glyph and the real price instead of typing prices into labels.

## Rules to respect
- Paid random items (loot boxes, eggs bought with Robux) must show their odds to the player before purchase, and are not allowed for players in some countries: gate with `PolicyService:GetPolicyInfoForPlayerAsync(player).ArePaidRandomItemsRestricted`.
- No selling of anything for real money outside Roblox, no off-platform links in purchase flows.
- Do not build pay-to-win mechanics or dark patterns (fake timers, misleading buttons) even if asked casually; say plainly what the request would do and offer the fair version.
- Testing: purchases in Studio are simulated and free. Tell the user to test real ones in a private server after publishing.
