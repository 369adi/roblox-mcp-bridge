# Reference: saving player data
Load it for: DataStores, saving and loading, leaderboards that persist, data loss bugs, migrating saved data

Ask before adding saving to a game that has none, and ask what must persist. If the place already has a data module (ProfileService, ProfileStore, DataStore2, their own), use it and follow its conventions; never add a second system beside it.

## Rules that prevent data loss
1. **One owner.** A single server ModuleScript (for example `ServerScriptService.PlayerData`) loads, holds and saves every player's data. Other scripts call its functions (`Get`, `Add`, `Set`); nothing else touches the DataStore.
2. **Never save defaults over real data.** If loading fails, kick the player with a clear message. Do not let them play on a fresh profile.
3. **`UpdateAsync`, not `SetAsync`,** for player data, so a stale server cannot overwrite a newer save.
4. **Session lock.** Store which server holds the profile. If another live server holds it, wait and retry, then kick. Without this, rejoining quickly duplicates or rolls back items.
5. **Save on leave, on shutdown and on a slow timer** (every 60 to 120 s). Never on every change.
6. **Budget.** Requests are limited per minute (roughly 60 + 10 per player for writes). Queue or coalesce; never write in a loop.
7. **Version the key and the data.** Key `Player_<UserId>`, store name with a version suffix, and a `Version` field inside the data for migrations.
8. **Only store plain data**: numbers, strings, booleans, arrays, dictionaries with string keys. No Instances, Vector3, Color3, CFrame, functions, or mixed tables. Convert (`{x, y, z}`) on the way in and out. Keys must be strings; a table with numeric gaps becomes a dictionary.
9. **Under 4 MB per key**, in practice far less. Store ids and counts, not whole item definitions.

## A complete module
```lua
--!strict
local DataStoreService = game:GetService("DataStoreService")
local Players = game:GetService("Players")
local RunService = game:GetService("RunService")

local store = DataStoreService:GetDataStore("PlayerData_v1")
local LOCK_SECONDS = 120
local AUTOSAVE_SECONDS = 90

local DEFAULT = {
	Version = 1,
	Coins = 0,
	Inventory = {} :: { [string]: number },
}
export type Profile = typeof(DEFAULT)

local PlayerData = {}
local profiles: { [Player]: Profile } = {}
local loaded = Instance.new("BindableEvent")
PlayerData.Loaded = loaded.Event

local function deepCopy<T>(value: T): T
	if typeof(value) ~= "table" then return value end
	local copy = {}
	for k, v in value :: any do copy[k] = deepCopy(v) end
	return copy :: any
end

local function reconcile(data: any, template: any)
	for key, value in template do
		if data[key] == nil then data[key] = deepCopy(value)
		elseif typeof(value) == "table" and typeof(data[key]) == "table" then reconcile(data[key], value) end
	end
end

local function key(player: Player) return "Player_" .. player.UserId end

local function load(player: Player)
	local data
	for attempt = 1, 5 do
		local locked = false
		local ok, err = pcall(function()
			store:UpdateAsync(key(player), function(old)
				old = old or { Data = deepCopy(DEFAULT) }
				local lock = old.Lock
				if lock and lock.JobId ~= game.JobId and os.time() - lock.Time < LOCK_SECONDS then
					locked = true
					return nil -- leave it untouched
				end
				old.Lock = { JobId = game.JobId, Time = os.time() }
				data = old.Data
				return old
			end)
		end)
		if ok and data then break end
		if not ok then warn("[PlayerData] load failed:", err) end
		data = nil
		task.wait(locked and 6 or 2)
		if not player.Parent then return end
	end
	if not data then
		player:Kick("Your data could not be loaded. Please rejoin in a moment.")
		return
	end
	reconcile(data, DEFAULT)
	if not player.Parent then return end
	profiles[player] = data
	loaded:Fire(player, data)
end

local function save(player: Player, release: boolean)
	local data = profiles[player]
	if not data then return end
	local ok, err = pcall(function()
		store:UpdateAsync(key(player), function(old)
			old = old or {}
			if old.Lock and old.Lock.JobId ~= game.JobId then return nil end -- another server owns it now
			old.Data = data
			old.Lock = if release then nil else { JobId = game.JobId, Time = os.time() }
			return old
		end)
	end)
	if not ok then warn("[PlayerData] save failed for", player.Name, err) end
end

function PlayerData.Get(player: Player): Profile? return profiles[player] end

function PlayerData.WaitFor(player: Player): Profile?
	while player.Parent and not profiles[player] do task.wait(0.1) end
	return profiles[player]
end

Players.PlayerAdded:Connect(load)
for _, player in Players:GetPlayers() do task.spawn(load, player) end

Players.PlayerRemoving:Connect(function(player)
	save(player, true)
	profiles[player] = nil
end)

task.spawn(function()
	while true do
		task.wait(AUTOSAVE_SECONDS)
		for player in profiles do
			task.spawn(save, player, false)
			task.wait(0.5)
		end
	end
end)

game:BindToClose(function()
	if RunService:IsStudio() then task.wait(1) return end
	local pending = 0
	for player in profiles do
		pending += 1
		task.spawn(function() save(player, true); pending -= 1 end)
	end
	while pending > 0 do task.wait() end
end)

return PlayerData
```
Change values through the profile table (`profile.Coins += 10`), on the server only, then mirror what the client needs (leaderstats, attributes, or a remote).

## Showing data to the player
- `leaderstats` values, or attributes on the player, set by the server whenever the profile changes. The client reads them; it never writes them.
- For bigger state (inventory), send a snapshot through a RemoteEvent on load and deltas after each change.

## Global leaderboards
- `OrderedDataStore` holds one integer per key. Write the player's score on save (not on every change). Read the top N with `GetSortedAsync(false, N)` on a timer (every 60 s or more) and cache the page for all clients.
- Names: `Players:GetNameFromUserIdAsync` in `pcall`, cached.

## Migrating old data
- Bump `Version`. On load, if `data.Version < 2`, transform fields, then set the version. Keep migrations in order and never delete one.
- Renaming a store abandons everyone's data. Ask before changing a store name or key format.

## Studio
- DataStores work in Studio only with Game Settings > Security > "Enable Studio Access to API Services", and only in a published place. A 403 or "API access" error in a test is that setting, not a code bug: tell the user.
- Test in Studio writes to the live stores of that place. Say so before running destructive tests.

## Diagnosing "my data did not save"
Check in this order: the place is published and API access is on; the save ran (`BindToClose` present, no early return); the data contains only storable types (an Instance or a NaN makes the whole save fail); the key is the same on load and save; another script is not overwriting with `SetAsync`; request budget warnings in the Output.
