# Почему Brickwire 1.0 не работал (и что исправлено в 1.1)

Каждая причина воспроизведена экспериментом в sandbox до исправления.

| # | Где | Что ломалось | Исправление |
|---|---|---|---|
| 1 | Мост ↔ StudioMCP | StudioMCP отдаёт **0 инструментов**, пока Studio не подключилась, и не шлёт `tools/list_changed`. Старый мост показывал зелёный `MCP_READY` с 0 tools и больше не запрашивал список → каждый вызов = `unknown tool`. | Повтор `tools/list` после init, периодический `ensureTools()`, повторный запрос при `unknown tool`. 0 tools = жёлтый статус, а не зелёный. |
| 2 | Запуск StudioMCP | Через `%LOCALAPPDATA%\Roblox\mcp.bat`, где зашит путь к одной версии Studio — ломается после обновления Studio. | Мост сам находит новейший `StudioMCP.exe` в `Roblox\Versions\*` (рядом с `RobloxStudioBeta.exe`); `mcp.bat` — только запасной вариант; `BRICKWIRE_STUDIO_MCP_PATH` для ручного пути. |
| 3 | Результаты | Ошибка Luau приходит обычным текстом (`Error executing code: …`, `isError=false`) → мост сообщал модели «success». | Текст результата проверяется; такие ответы помечаются `error`. Обрыв связи со Studio → один повтор, затем честная ошибка. |
| 4 | DeepSeek | Кнопка отправки DeepSeek во время генерации становится **STOP** (без aria-label). Старый адаптер не видел генерацию, на паузе стрима считал ответ готовым, слал напоминание и «нажимал Send» = **обрывал ответ**. Цикл умирал, инструмент не выполнялся. | Отдельный DeepSeekAdapter: распознаёт STOP по иконке, `.ds-loading`, рост текста (12 с для рассуждения / 1.2 с для ответа); во время генерации ничего не нажимает; ждёт стабильный ответ. |
| 5 | Тесты | Mock-страницы были подогнаны под адаптеры (фейковый aria-label "Stop"), поэтому тесты проходили, а живой поток — нет. | Новый `tests/e2e/deepseek-live.e2e.test.ts`: реалистичная реплика DeepSeek + stand-in StudioMCP, который ведёт себя как настоящий (0 tools до подключения, ошибки текстом) и **реально исполняет Luau** (luau CLI). Старые mock-тесты оставлены как DOM-smoke. |

## После первого живого теста (1.1.1 – 1.2)

| # | Что ломалось | Исправление |
|---|---|---|
| 6 | DeepSeek в каждом ответе нумерует вызовы с `"c1"`. Агент помнил id за всю сессию и **молча пропускал** новый вызов с тем же id → «No tool call — reminder». | Дубликат = тот же ответ (индекс хода) + тот же вызов. Новый ответ всегда выполняется. |
| 7 | Длинный Luau внутри JSON-строки: модель ломает экранирование `"`/`\n` → вызов невалиден или обрезан. | Сырой блок `<ROBLOX_LUAU>` (как `###LUA###` в ZeroScript). Тест: скрипт на 245 строк с кавычками всех видов выполняется целиком. |
| 8 | Почти любой строительный код содержит `:Destroy()` / цикл по `GetChildren()` → режим auto спрашивал подтверждение на каждом шаге; в окне было видно 6 строк кода. | Режим подтверждений в панели (для каждой нейросети свой), режим *Full auto*, кнопка *Approve all (session)*, полный код в окне подтверждения. |

## Что НЕ проверено

Настоящий Roblox Studio и живой chat.deepseek.com в sandbox недоступны. Финальная проверка — на вашей машине:
`start.bat` → READY → DeepSeek → Start Agent → 3 задачи, и `node scripts/studio-e2e.mjs` (7 шагов через `execute_luau`).

## 1.5: «иногда ответ не отправляется ИИ»

Найденные причины и исправления:

1. **Фоновая вкладка.** Пока вы смотрите в Studio, вкладка чата скрыта, и Chrome замедляет `setTimeout/setInterval`
   (через ~5 минут — до одного раза в минуту). Агент «зависал» между шагами. Теперь все таймеры агента
   (`extension/src/core/clock.ts`) получают тик от service worker каждые 250 мс через порт `bw-clock` —
   такие сообщения не замедляются.
2. **Свой текст принимался за черновик пользователя.** Если сайт не очистил поле после отправки, следующий
   результат ждал, «пока пользователь отправит черновик». Теперь остаток нашего сообщения распознаётся
   (и черновик-задача при Start тоже).
3. **Тихая потеря сообщения сайтом.** Поле очистилось, но сообщения в ленте нет. Теперь каждое сообщение
   несёт метку `[bw:xxxxx]`; сторож доставки проверяет её появление и переотправляет (до 4 раз), затем
   пауза + «Resume» отправит снова. Тест: `E2E delivery watchdog` (сайт-реплика теряет первое сообщение).
