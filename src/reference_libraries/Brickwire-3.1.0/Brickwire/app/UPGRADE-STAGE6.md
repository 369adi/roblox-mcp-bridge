# Brickwire 3.0 (Stage 6)

## Запуск
```
npm install && node app/build.mjs     # сборка bridge + plugin (rbxmx)
start.bat / ./start.command            # bridge на 127.0.0.1:<BRICKWIRE_PORT>
открыть http://127.0.0.1:<порт>/app#chats
```
LLM (для чата/Super Mode): `BRICKWIRE_LLM_PROVIDER`, `BRICKWIRE_LLM_URL` (OpenAI-совместимый), `BRICKWIRE_LLM_MODEL`, ключ провайдера. Без LLM работает локальная генерация 3D; текстовые запросы получают статус `blocked` с причиной.

## Архитектура (bridge/src/bw3/)
| Модуль | Назначение |
|---|---|
| skill-packs.ts, skill-meta-50.ts, skills-service.ts | загрузка паков навыков, валидация, маршрутизация, композиция контекста, история использования |
| mesh-kit.ts, asset-forge.ts | процедурные меши, валидация, OBJ/MTL, рендер превью |
| artifact-store.ts | хранилище артефактов (data/artifacts-v1), проверка целостности sha, импорт-пейлоад |
| run-store.ts | реальные события/стадии запусков (data/bw3-runs-v1), отмена, восстановление после рестарта |
| llm.ts | стриминг, ретраи, список моделей |
| orchestrator.ts | чаты, Standard/Super Mode, план DAG, проверки, цикл исправлений, approvals |
| devtree.ts | детальное дерево запуска (шаги, вызовы, файлы, проверки) |
| chat-graph.ts | граф Development Tree для каждого чата: результаты, цепочки, «Best next move» |

## Пересылка в AI-чат (Notion и др.)
Если запрос нельзя выполнить локально (3D-объект вне 10 семейств или нет настроенной LLM), а вкладка AI-чата с расширением Brickwire подключена, запрос пересылается туда (путь `browser-agent`): расширение вводит его в чат, ответы и вызовы инструментов зеркалируются в карточку прогресса и Development Tree, «ask» агента возвращается вопросом в чат. Отчёт агента без критериев приёмки отмечается мостом как PARTIAL (событие в запуске) — не выдаётся за проверенный. В шапке чата — статус «AI-чат: Notion AI».

## Development Tree (у каждого чата своё)
- В чате переключатель «Чат | Дерево»; в разделе Development Tree — выбор чата и вид «Граф | Детали».
- Граф: корень — чат (переименование ✎), шестиугольники — реальные результаты запусков (✓ готово, ! частично, ✕ ошибка/блок, анимация — выполняется), стрелки — продолжения (запуск, созданный через Add, вешается на исходный результат), пунктир — предложения.
- Предложения («Best next move» + Add) строятся по правилам из типа результата (не LLM); выполняются только по клику Add: отправка промпта в этот же чат, импорт в Studio (с подтверждением) или вариант.
- Клик по узлу: открыть сообщение, 3D-просмотр, «Шаги и вызовы» (детальное дерево запуска). Панорама мышью, зум колесом, Fit.
- API: `GET /api/bw3/chats/:id/graph`.

## 50 Skills
Пак скопирован байт-в-байт в `bridge/skills/packs/brickwire-50/`. SkillService читает каждый SKILL.md целиком (frontmatter + тело + ресурсы), проверяет зависимости/конфликты, строит таблицу маршрутизации (`skill-meta-50.ts`). На каждый запрос: роутинг → выбранные навыки (+ meta 46 всегда, 47/49 для сложных, 48 для 3D) → полный текст в контекст агента → история использования. UI: раздел Skills (включение, закрепление, авто-режим, просмотр SKILL.md, предпросмотр роутинга); в чате видны выбранные навыки до отправки.

Известный дефект архива: все SKILL.md ссылаются на `../../_shared/GLOBAL_RULES.md` (на уровень выше нужного). Загрузчик разрешает его в `_shared` пака и пишет предупреждение.

## Ограничения
- Процедурная генерация: 10 семейств (дракон, меч, дом, башня, машина, дерево, камень, кристалл, сундук, бочка); прочее → честный статус unsupported.
- MTL — только цвета, без текстур.
- Импорт в Studio через EditableMesh не сохраняется в place (persistent:false, предупреждение в UI).
- Реальные Roblox Studio, Blender и платные LLM не проверялись — только тестовые фикстуры.
