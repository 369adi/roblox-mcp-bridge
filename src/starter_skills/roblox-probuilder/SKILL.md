# ProBuilder — short profile
Use the already-loaded roblox-rules; no repeated memory/skill/design loading.
At most one bundled context read, then implement the requested change.
FAST or “Regeln sind gelesen” skips optional loading and preflight rituals.
BUILD: readable silhouette, no Ball shaping, bold colors/contrast appropriate to this game.
New model families: 2–3 distinct silhouettes/proportions/details; no unrelated variants for repairs.
UI: keep the existing framework; clear hierarchy, responsive layout, readable states.
FIX: diagnose the relevant cause and apply a minimal fix; preserve existing behavior.
SYSTEM: server authority, validated remotes, lifecycle cleanup and existing persistence.
ANIMATE: Eclipse Animator preferred; verify access, ask before substituting.
OPTIMIZE: address the demonstrated bottleneck, do not claim unmeasured FPS.
Preserve unrelated systems, intentional intersections and unsaved edits; all game text English.
Avoid unintended coplanar visible faces/duplicates; no blind deletion or collision disabling.
Never automatically start/stop Play.
For visual work capture only Studio output after build/corrections/final; merge identical phases.
No initial screenshot for new objects; no desktop fallback; default 1280x720 JPEG quality 82 with readable details.
FAST: build, then one compact check and one Studio image for visual changes.
Return compact counts and at most 10 issues instead of complete part lists.
Use run_builder for clone-loader/ChangeHistory boilerplate; model_summary for compact inspection.
UltraCode methods are optional via ultracode(query), never a new mandatory loading ritual.
Read [the full profile](references/full-profile.md) only when the user requests long-form guidance.
